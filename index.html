fixagent is an AI agent that fixes bugs in Python, C++ and Rust repositories. A fix only counts if the tests fail before it runs and pass after.

View the code on GitHub Run the demo

One bug, from report to patch.

Give fixagent a repository and a bug report, or a GitHub issue number. It explores the code, runs the tests, edits the source and runs the tests again. Pick one of the demo bugs and replay the fix, step by step.

py_stats_median

median() returns the wrong value for lists with an even number of items. median([4, 1, 3, 2]) returns 3, but the median should be 2.5.

  1. Run testsTests fail
  2. Read filestats.py
  3. Edit filestats.py
  4. Run testsTests pass
  5. Finish
Fixed

The tests failed before the agent ran and pass now. Agent’s note: Averaged the two middle values. Shown in demo mode, which replays a scripted model rather than a real one.

It can’t cheat its way to green.

An agent that edits code and runs commands needs limits. These are built into the tools, so the model cannot talk its way around them.

  • It works on a copy.Your repository is never modified.
  • Every path stays inside that copy.Symlinks included.
  • Test files are read-only.The agent cannot pass by weakening a test.
  • Commands come from a short allowlist.They run without a shell and with a timeout.
  • The model’s claim of success is ignored.The runner re-runs the tests itself.

fixagent still runs the repository’s own build and test code. For code you do not trust, run it inside a container or virtual machine.

Three languages, no heavy dependencies.

Python

The agent loop, the tools, the verifier and the dashboard’s API server. No third-party runtime dependencies.

  • Agent loop fixagent/agent.py
  • Tools and sandbox rules fixagent/tools.py
  • Run and verify one issue fixagent/runner.py
  • Open a pull request fixagent/pullrequest.py
  • Fix-rate evaluation fixagent/evaluate.py

Rust

A small command-line tool that gives the agent fast code search. It uses only the standard library, and the agent falls back to Python without it.

  • Fast code search tools/codesearch/

React

A TypeScript dashboard that shows each bug, the agent’s steps as they happen, the verdict and the patch.

  • Dashboard dashboard/

Run it on your machine.

You need Python 3.10 or newer. The C++ and Rust demos also need g++, make and cargo.

Get the code and run the tests

The tests run offline and need no API key.

git clone https://github.com/AmitDas856/fixagent.git
cd fixagent
pip install pytest
python -m pytest

Watch it in the dashboard

With no model settings the server starts in demo mode and replays a scripted model for the demo bugs. Needs Node.js 20 or newer. Then open http://127.0.0.1:8000.

cd dashboard
npm install
npm run build
cd ..
python -m fixagent.server --tasks demo_repos/tasks.json

Fix one bug with a real model

fixagent talks to any server with an OpenAI-style /chat/completions endpoint that supports tool calling, including a local model through Ollama.

export FIXAGENT_BASE_URL="https://your-provider.example/v1"
export FIXAGENT_MODEL="your-model-name"
export FIXAGENT_API_KEY="your-key"

python -m fixagent \
  --repo demo_repos/cpp_strutil \
  --issue 'trim("  hello  ") returns "hell" instead of "hello"' \
  --out fix.patch --log run.jsonl

Fix a GitHub issue and open a pull request

Needs the GitHub CLI, signed in. The fix goes on a new fixagent/... branch, and a pull request is only opened when the fix is verified.

python -m fixagent --repo path/to/your/checkout \
  --github-issue 12 --open-pr

What is tested, and what is not yet.

A tool that only trusts evidence should be clear about its own.

Tested

  • 68 tests run offline, using a scripted stand-in for the model that replays the tool calls a real model would make.
  • The agent fixes all three demo bugs in that setup.
  • It is correctly marked as failed when it makes a wrong fix, changes nothing, tries to edit the tests or runs out of steps.
  • The pull request step is tested against a local git remote. The dashboard’s API server is tested over real HTTP.

Not done yet

  • It has not been run with a real model. That needs an API key or a local model.
  • The pull request step has not been run against the real GitHub API.
  • The evaluation covers three small demo bugs, not a public benchmark.
  • The dashboard has no automated browser tests, and the experimental Hack support has not been run with HHVM.
